How I work

Design Thinking, run as a full loop.

I do not start with screens. I start with people, frame the real problem, write it down so engineering can build it, then test each solution against what users actually do.

01

Empathize

Interviews, shadowing, and journey research to understand the human, not the assumption.

02

Define

Synthesize into a sharp problem, a value map, and a written requirements baseline.

03

Ideate

Turn value into prioritized user stories with clear acceptance criteria.

04

Prototype

Lo-fi to hi-fi, each fidelity built to answer a different question, fast.

05

Test

Usability sessions and UAT, feeding evidence and defects straight back into the loop.

Define · From needs to a baseline

I turn research into requirements a team can own.

A business requirements document sets the baseline. A traceability matrix keeps every business need linked to a story, an acceptance criterion, and a test, all the way to release.

BRD · v1.2

Digital learning activation

Objective
Raise week-one activation and 7-day retention for new students.
Scope
In: onboarding, reading, progress. Out: payments, admin portal.
Stakeholders
Students, teachers, content team, engineering.
Business requirements
BR-1 Reduce setup friction BR-2 Show progress BR-3 Surface struggling students
Success metrics
Activation rate, D7 retention, setup completion time.

Test · User acceptance testing

I close the loop with UAT.

Test scenarios written from the acceptance criteria, run with real users, defects logged and clarified with engineering, and a clear gate before release.

UAT-1Pass

New student sets up unaided

Open device, follow setup, reach the first lesson.

Expected: reading within 3 steps, no help needed.

UAT-2Pass

Returning student sees progress

Reopen the app after a day away.

Expected: streak and next goal shown first.

UAT-3Fail

Teacher spots struggling students

Open the class dashboard.

Expected: low-activity flagged. Defect: flag delayed, logged and clarified.

Release acceptance
Approved when all P1 scenarios pass and no blocking defect is open.

The lens I bring

HCI principles, applied to every flow.

01

Reduce cognitive load

Fewer choices per screen, progressive disclosure, defaults that do the thinking.

02

Recognition over recall

Show options in context instead of asking people to remember them.

03

Visible feedback

Every action confirms itself, so the user always knows the system state.

04

Consistency

Patterns behave the same everywhere, so learning one screen teaches the rest.

05

Error prevention

Design out the mistake before it happens, then make recovery painless.

06

Match the real world

Language and flow follow how people actually think about the task.
